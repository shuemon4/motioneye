# Pi 4 Video Stream Fix - 20251223-1808

## Issue Summary

**Problem**: Video stream not displaying on Pi 4 (192.168.1.246). UI showed spinning loader instead of live camera feed.

**Symptom**: Browser DevTools would show failed requests to Motion's stream endpoint.

**Affected Configuration**:
- Device: Raspberry Pi 4
- Motion Version: 5.0.0
- Camera: libcamera Camera (imx219)
- Streaming Mode: Direct streaming enabled

## Root Cause

MotionEye was using an **incorrect endpoint path** for Motion 5.0's MJPEG stream.

**Incorrect path** (legacy Motion 4.x format):
```
/1/mjpg/stream
```

**Correct path** (Motion 5.0 format):
```
/1/mjpg
```

Motion 5.0 changed the webcontrol stream endpoint structure. The `/stream` suffix is no longer part of the path.

## Evidence

### Test Results

```bash
# WRONG - Endpoint doesn't exist, times out
curl 'http://localhost:7999/1/mjpg/stream'

# CORRECT - Returns multipart MJPEG stream
curl 'http://localhost:7999/1/mjpg'
# Result: 1.7MB in 3 seconds (~566 KB/s)
# Format: multipart/x-mixed-replace with JPEG boundaries
```

### Stream Data Verification

The correct endpoint returns valid MJPEG multipart stream data:
```
--BoundaryString\r\n
Content-type: image/jpeg\r\n
Content-Length: 21718\r\n
\r\n
[JPEG data...]
```

## The Fix

**File**: `motioneye/static/js/main.js`
**Line**: 5845

### Change Applied

```javascript
// BEFORE (incorrect for Motion 5.0)
var directUrl = 'http://' + window.location.hostname + ':' +
                this.config['streaming_port'] + '/1/mjpg/stream';

// AFTER (correct for Motion 5.0)
var directUrl = 'http://' + window.location.hostname + ':' +
                this.config['streaming_port'] + '/1/mjpg';
```

**Commit Context**: Part of Motion 5.0 compatibility updates alongside CSRF token support and POST method enforcement.

## Deployment and Verification

### Deployment Steps

1. Fixed endpoint in `motioneye/static/js/main.js:5845`
2. Deployed to Pi 4:
   ```bash
   rsync -avz motioneye/static/js/main.js admin@192.168.1.246:~/motioneye/motioneye/static/js/
   ```
3. Restarted MotionEye service:
   ```bash
   ssh admin@192.168.1.246 "sudo systemctl restart motioneye"
   ```

### Verification

**Expected Result**:

- No more spinning loader

**Test**:

## Related Changes

This fix is part of the broader Motion 5.0 migration that includes:
- CSRF token support (`motioneye/motionctl.py`)
- POST method enforcement for state-changing operations
- Removal of `stream_port` configuration (uses `webcontrol_port` instead)
- libcamera-only support (MMAL removed)

**Scope**: All cameras using Direct Streaming mode with Motion 5.0+

**Backward Compatibility**: This change is specific to Motion 5.0+. Motion 4.x compatibility is no longer supported in this fork.

**CPU Impact**: No change to CPU usage. Direct streaming mode continues to provide lowest CPU overhead by streaming directly from Motion without MotionEye proxy.
